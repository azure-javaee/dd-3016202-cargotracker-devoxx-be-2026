## Implement

- Add pinned agent and collector configuration under `demo/observability/` and document local reproduction.
- Layer instrumentation onto task 2.5's single bounded Liberty lifecycle; do not create another server lifecycle.
- Use a fixed CI request identifier to correlate request transcript, HTTP path/status, trace/span identifiers, Liberty/application logs, and collector output.
- Exercise one successful seeded request and one controlled invalid request.
- Export traces and nonempty JVM/runtime metrics in machine-readable form with deterministic sampling for the exercised requests.
- Add explicit artifact redaction and secret-pattern checks. Never retain request bodies, credentials, raw environment dumps, or unnecessary cargo data.
- Stop Liberty and the collector in always-run cleanup.

## Completion gates

- Collector health and Liberty readiness use bounded waits.
- Both requests can be traced from transcript through telemetry and relevant logs with service, operation, status, timestamp, and trace identity.
- Controlled failures prove explicit diagnostics for collector unavailable, incompatible instrumentation, missing telemetry, broken correlation, secret-like artifact content, and an invalid request without a diagnosable signal.
- Upload immutable `otel-telemetry` and applicable `liberty-logs` artifacts with schema-1 metadata, nonempty inventories, redaction result, and 90-day retention.
- Required CI is green and the evidence-matrix update records the exact run, SHA, job, artifact URL/ID/digest, supporting file, observed event, confidence, and slide implication.

## Out of scope

- Azure Monitor, Application Insights, Azure credentials/resources, MicroProfile feature migration, application API changes, or a second runtime lifecycle.
- Claiming OpenTelemetry log export works if only separately correlated Liberty logs are reliable.
- Performance comparison and JVM tuning, which belong to task 2.7.
