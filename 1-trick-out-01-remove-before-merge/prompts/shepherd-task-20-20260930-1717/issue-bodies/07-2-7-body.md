- Run five cycles ordered: direct/bypass/tuned, bypass/tuned/direct, tuned/direct/bypass, direct/tuned/bypass, bypass/direct/tuned.
- Record runner CPU, memory, OS, kernel, cgroup view, startup, request distribution, RSS, CPU, heap, GC, JFR, effective commands/flags, launch ancestry, exit status, duration, and cleanup.
- Capture tuned `JAZ_DRY_RUN=1`; reject user tuning, missing selected tuning, unexpected tuning in bypass/direct, artifact/workload mismatch, or surviving processes.
- Reuse task 2.6 diagnostics to explain anomalies.

## Completion gates

- Every mode uses identical artifacts, readiness, requests, JFR profile, diagnostics, and host envelope.
- Fail on startup beyond 90 seconds, request timeout/non-200/missing seed, crash/OOM, complete repetition beyond 120 seconds, provisional peak RSS above 2 GiB unless hosted evidence justifies widening, missing/unparseable diagnostics, or cleanup failure.
- Do not fail merely because one mode has different ordinary timing, CPU, heap, RSS, or GC measurements.
- Upload immutable `performance-java`, `performance-jaz-bypassed`, `performance-jaz-tuned`, and `performance-comparison` artifacts with metadata and safe bounded evidence.
- Complete required CI and merge the evidence-matrix update before tagging the tricked-out baseline.

## Out of scope

- Containers, synthetic/privileged cgroups, fixed heap/processor/GC tuning, startup JFR flags, `JAZ_IGNORE_USER_TUNING`, or changing application code to favor a launcher.
- Declaring a performance winner from hosted-runner noise.
- AKS-limit evaluation, which belongs to separate Azure deployment work.
