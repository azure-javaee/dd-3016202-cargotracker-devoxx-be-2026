## Section 8: Observations and Recommendations

### 8.1 What Worked Well

- **Post-merge resume was idempotent.** The shepherd detected the merged PR and avoided duplicate review, code, or merge operations.
- **Exact-SHA verification was explicit.** CI was tied to the immutable merge SHA rather than inferred from earlier head checks.
- **Evidence gates were durable.** The merged evidence-matrix entry and all four cited PR-run performance artifacts were reverified.
- **The outcome protocol was honored.** The final response emitted `SHEPHERD COMPLETE`, and the manifest recorded a matching successful status and exit code.
- **Lesson treatment remained observable.** `lessonPropagation: off` was preserved in both invocation and manifest.

### 8.2 What Could Be Improved

- **The controller launched a full Stage 40 session for post-merge verification.** Most of the 10m 44s session was a CI wait; a dedicated resume mode could reduce setup and context cost.
- **The current run has no direct link to its predecessor.** The recovery relationship had to be inferred from the parent job log and prior post-mortem.
- **Token observability remains incomplete.** Cache tokens are visible, but input and output totals are redacted.
- **The issue remained open after merge until this recovery run.** Merge automation should close or explicitly queue issue closure once exact-SHA gates succeed.

### 8.3 Recommendations

1. Add a structured `post_merge_resume` state to Stage 40 with PR number, merge SHA, pending gates, predecessor run directory, and reason for resumption.
2. Persist a machine-readable stage outcome after each gate so retries can skip already verified work without rereading the full plan.
3. Have the controller correlate successive runs for the same campaign/task and report combined lifecycle metrics separately from per-run metrics.
4. Preserve the current exact-SHA and artifact-expiry checks; they provide stronger completion evidence than relying on PR state alone.
5. Keep treatment metadata such as lesson propagation in every manifest and report so control and campaign-mode runs remain comparable.
